Status: proposed 2026-10-29. Mockups:
- `docs/mockups/saved-agents.html` covers Crew, its members and the Lead.
- The 1.7.5 mockup is still to come.

The evidence comes from about 1,270 owner prompts since 2026-07-20, mined from the session transcripts, plus a test drive of saved agents with the real `code-reviewer` agent.

- Most of the size saving comes from removing dictation.

## The Crew release (after 1.7.5)

### Remove the Orchestrator entirely

- **Scope:** about 126 files and 18,600 lines.
- **Main process:** `src/main/orch/*`, including its MCP server, dispatcher and archive.
- **Renderer:** `src/renderer/components/orch/*`, `orchActions.ts`, `commands/orchestrator.ts` and `orchestrator.css`.
- **Shared code:** `src/shared/orch/*`.
- **Wiring:** orchestrator references in IPC, preload, settings schema and transfer, attention, topbar, appShell, layouts, sessionIndex, ptyManager and agentLaunch.
- **Work dashboard:** it stops counting orchestrator runs.
- **Tests:** the `orchestrator*.spec.ts` specs.
- **Settings and data:** remove the `experimental.orchestrator` setting. Existing run archives on disk are left untouched and are not migrated. Settings load ignores the old keys.

### Remove voice dictation entirely

- **Code:** 17 files, about 2,000 lines. That covers `src/renderer/dictation/*`, `dictationSettings.ts` and the dictation intro.
- **Settings:** the Settings "Voice dictation" section, the microphone permission handling it alone needs, and its e2e specs.
- **Dependencies:** `@huggingface/transformers` and `onnxruntime-node`/`-web`.
- **Size:** together with the packaging fixes in 1.7.5 item 11, this is most of the app-size saving. The 22.5 MB WASM and the 211 MB runtime go with it.
- **Data:** downloaded speech models in app data are removed on first start of the new version, with a note in What's New.

### Turn any skill into a crew member

- **Where:** every skill in the Skills view gets "Make a crew member", and several can be converted at once.
- **What Dawsha fills in from the skill:**
  - name and role from the description;
  - the fields to ask for, such as an id and dev/stage/uat;
  - permissions ("read-only");
  - the projects it mentions;
  - a paste-to-run pattern.
  The dialog shows where each choice came from, and everything is editable before saving.
- **Linking:** the member stays linked to its skill file. Claude loads the skill natively; on Codex and Gemini the member's instructions tell it to read `SKILL.md` first.

### Remote Access, refined (desktop and phone)

The mockup is `docs/mockups/remote-and-skills.html`.

- **Desktop status line:** one plain line says whether the phone can reach this PC, with Reconnect when the tunnel drops. This fixes the silent drop from the owner's sessions.
- **Desktop health panel:** tunnel type, round trip, last check, when the link last changed, and which phones are online.
- **Desktop settings:** auto-reconnect, and "tell me when the link changes".
- **Desktop permissions:** per-capability permissions for phones. Removing a phone asks first and names it. A short log of phone actions.
- **Phone app, design rules:** the owner's rules apply (no ALL-CAPS labels, no pills, no boxed cards), and crew identities replace the letter tiles.
- **Phone app, layout:** questions come first, with large buttons. Agent-specific choices are offered, for example "Draft only" or "Post comments" for Rami.
- **Phone app, Crew tab:** run a member, or give Maya a goal, from the phone.

### Crew

The working name is "Crew"; the mockup's strip lets the owner compare it with Squad, Team and Bench.

- **Members:** each member has an identity (name, role, colour, initials) and a job (instructions, a prompt with `{{fields}}`, a default model, effort, permissions and projects).
- **Built-in members:** eight ship with Dawsha:
  - Maya, the Lead
  - Sami, code reviewer
  - Tarek, debugger
  - Omar, builder (works in its own worktree, never pushes)
  - Hana, tester
  - Lina, UI polisher (the owner's taste rules)
  - Nour, docs and releases
  - Yara, explainer

  Built-ins can be hidden and duplicated, but not edited in place or deleted.
- **Import:** brings in `~/.claude/agents/*.md` (with Claude Code's `color:` field), skills and Codex prompts. Imported members stay linked to their files.
- **Live state on the avatar:** working (a breathing ring), needs you (three flashes, then steady), done (one flash, then ✓) and failed (✕). Every state also shows a word, and reduced motion is respected. A top-bar crew strip shows who is on a job.
- **Running members:** every run starts in a project folder or worktree, as a normal pane titled "Rami · PR 8841".
  - **Model per run:** Claude Fable, Opus, Sonnet or Haiku, Codex or Gemini.
  - **Lean start by default:** `--strict-mcp-config`, about 40% cheaper than a skill in the test drive.
  - **Paste to run:** paste an id, a PR link or a build URL and Dawsha suggests the member, with the fields filled.
- **The Lead (Maya)** takes a goal and a project and proposes a plan: which member does what, on which model, at what estimated cost.
  - **Owner defaults, on out of the box:**
    - a few big jobs;
    - one review at the end;
    - at most two members at once;
    - show the plan first;
    - ask before pushing, merging, posting or deleting.
  - **Budget:** a budget per goal.
  - **Mechanism:** she drives members through a new `dawsha crew run|status|result` CLI over the existing pipe, so every job is a normal, visible pane.
  - **Optional:** the Lead is only needed for multi-member goals. Members can always be run directly.
- **Measured costs** (code-reviewer on a small commit, Sonnet):

  | Run | Cost |
  |---|---|
  | Saved agent | $0.22 |
  | Subagent | $0.25 |
  | Skill | $0.20 |
  | Lean saved agent | **$0.12** |

- **Per-CLI limits found in the test drive:**
  - **Codex:** its sandbox fails on this PC in both read-only and workspace-write modes, so Codex members run with full access and "read only" becomes an instruction.
  - **Gemini:** needs a login first, so Dawsha should check and offer one.
