# Dawsha 1.7: Files view, visual cleanup and tag colours, implementation plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or subagent-driven-development) to implement this plan task by task.

**Goal:** Ship 1.7 with a Files view (tree, file and changes, light editing, Ctrl+P), the 1.6.2 "boxed" look removed, the dim
toggle off by default, visible automatic tag colours, and the website section.

**Design:** `docs/plans/2026-10-26-1.7-files-and-polish-design.md`. **Mockups:** https://claude.ai/artifact/QgRxbpYXTCNJaQ811B7aST

**Architecture:** Main reuses `src/main/gitWorkspace.ts` (`projectFiles`, `readProjectFile`) and adds save, stat, a
merge-base diff and a debounced watcher behind IPC. Pure logic (tree building, filters, auto tags, the Agents scale) lives
in `src/shared/` and is unit tested. The renderer adds a `'files'` view, wired like the 1.6.2 `'background'` view, with
a CodeMirror 6 editor loaded lazily.

**Tech stack:** Electron, vanilla TS renderer (`h()` from `src/renderer/dom.ts`), vitest, Playwright e2e (`tests/e2e`),
CodeMirror 6 (`@codemirror/state`, `view`, `commands`, `language`, `search`, `merge`, plus language packs loaded with
`import()`).

**Conventions:**
- Match the surrounding code: short comments, plain naming, `h()` markup.
- Commit after each task with a Conventional Commit message ending in the Co-Authored-By trailer.
- Run `git commit` as its own command, because a hook blocks it when combined with other flags.
- Unit tests: `npx vitest run <file>`. E2E: `npm run build` then `npx playwright test <spec> --workers=1`.
- Reproduce CI layout bugs at 1024x728 by temporarily editing `src/main/index.ts:113-114`, and never commit that edit.

## Phase 2: Files view

### Task 7: Main side, covering save, stat, the base diff and the watcher

**Files:** `src/main/gitWorkspace.ts`, a new `src/main/fileWatch.ts`, `src/shared/gitStatus.ts`, `src/shared/ipc.ts`,
`src/shared/api.ts`, `src/preload/index.ts`, `src/main/ipc.ts`, `tests/unit/gitWorkspace.test.ts`.

1. `readProjectFile` also returns `mtimeMs`, so add it to `ProjectFileResult`'s ok variants.
2. `writeProjectFile(folder, path, text, expectedMtime)`. It validates like `readProjectFile`, resolves the path's real
   location with `realpath` on the parent folder and re-checks it with `insideRoot`, and refuses files over 1 MB or
   binary files. If the current `mtimeMs !== expectedMtime` it returns `{ ok:false, conflict:true }`. Otherwise it writes
   UTF-8, keeping the file's existing line endings (detect `\r\n` in the old text), and returns the new `mtimeMs`.
3. `fileAgainstBase(folder, path)`. It finds the merge base of `HEAD` with `origin/main`, `main` or `master` (the first
   that exists, else `HEAD`) and returns `{ ok:true, base: string|null, text }`, where `base` is `git show <mb>:<path>`
   (null for a new file).
4. `fileWatch.ts`: `watchProject(folder, onChange)` uses `fs.watch(root, { recursive: true })`, ignores `.git/` and
   `node_modules/`, debounces by 300 ms and passes the changed relative paths. IPC `files:watch` / `files:unwatch` keep
   one watcher per folder with ref counting. Events go to the window on `files:changed`.
5. Unit tests with a temp git repo, following the existing gitWorkspace tests: a write round-trips; a stale mtime gives
   a conflict; `../x` is refused; a symlink pointing outside is refused; the base text of a modified file equals the
   committed text.
6. Commit `feat: main side for the Files view`.

### Task 8: Shared logic for the tree, filters and quick open

**Files:** a new `src/shared/fileTree.ts` and `tests/unit/fileTree.test.ts`.

1. `buildTree(files: string[], status: Map<string,'M'|'A'|'D'|'R'|'?'>): TreeNode[]` sorts folders first, then
   files, case-insensitively. Folder badges count the changed files inside them.
2. `filterTree(nodes, mode: 'all'|'changed'|'sessions', sessionFiles: Set<string>, text: string)` keeps the ancestors
   of each match.
3. `quickOpen(files, query, recent: string[])` reuses `fuzzyMatch` from `src/shared/palette.ts` against the basename
   first and then the path. Recent files get a boost, and it returns the top 50.
4. Test first: ordering, ancestors kept, changed-only, a basename match beating a path match, recents first.
5. Commit `feat: file tree and quick open logic`.

### Task 9: Editor wrapper (CodeMirror 6)

**Files:** `package.json` (add `@codemirror/state`, `@codemirror/view`, `@codemirror/commands`, `@codemirror/language`,
`@codemirror/search`, `@codemirror/merge`, `@lezer/highlight`, and the language packs `@codemirror/lang-javascript`,
`lang-json`, `lang-markdown`, `lang-css`, `lang-html`, `lang-python`, `lang-xml`, `lang-yaml`, `lang-sql`,
`@codemirror/legacy-modes` for C#, shell and PowerShell, all pinned exactly), plus new files
`src/renderer/files/editor.ts` and `src/renderer/files/languages.ts`.

1. `languages.ts` maps an extension to an async loader (`() => import('@codemirror/lang-javascript').then(...)`), and
   unknown extensions get plain text.
2. `editor.ts` exports `createEditor(host, { text, path, readOnly, theme })` returning
   `{ setText, getText, setReadOnly, showChanges(baseText|null), showFile(), onDirty(cb), focus(), destroy() }`.
   - Read-only mode uses `EditorState.readOnly.of(true)` with `EditorView.editable.of(true)`, so selection, Ctrl+A,
     Ctrl+C and the native context menu still work. This is the "open and copy" requirement.
   - `showChanges` swaps in `unifiedMergeView({ original: base, mergeControls: false })`, read-only. `showFile`
     swaps it back. The toggle never loses the edit buffer.
   - The theme comes from CSS variables (`--bg`, `--text`, `--muted`, `--accent`) so every Dawsha theme works. The
     font is the terminal font family.
3. The bundle is loaded with `import('./files/editor')` the first time the Files view opens, so startup stays as fast.
4. Commit `feat: CodeMirror editor wrapper for the Files view`.

   keyboard works with arrows, Enter and Left/Right to fold. Filters: All / Changed / Open in sessions.
5. Right panel, "Sessions that touched it": open panes in this project whose timeline insights list the path (reuse the
