# Dawsha 1.7.3: Agents refinement, Files context, and run commands

Status: approved by the owner with “go on”; implemented locally on `feat/1.7.3`. See the implementation plan for verification results and the remaining full-suite teardown issue.

## Intent and scope

Make Agents easier to scan, and let a developer browse and run the selected checkout without leaving Dawsha. The owner requested this scope for **1.7.3**. Do not rename it 1.7.2 or publish anything as part of design work.

Keep the existing Electron/TypeScript, CodeMirror, theme ladder, context menus, and terminal infrastructure. No new UI framework or dependencies are needed for the proposed design. The HTML preview uses example content and never operates on actual files.

## Approach

Extend the existing Agents and Files views. A separate workspace manager would add navigation and duplicate the Files editor. A multi-root explorer was considered; the owner chose a **Visual Studio-style dropdown that switches the displayed checkout**. A single selected checkout also makes Delete and Run targets clear.

## Agents

- Compact, consistently aligned session headers, approximately 48–56px for two lines. Remove the excessive gaps visible in the supplied screenshot.
- Keep group totals beside the title: `31 agents · 29 done · 2 failed`. They remain visible when folded and at narrow widths; never position essential counts at the far end of an unbounded canvas.
- Raised neutral group headers, quiet seams between session groups, indented child rows, and a visible selected row. Avoid nested cards, coloured side stripes, pill badges, and decorative progress bars.
- Use existing theme tokens: blue for running, quiet success green for done, and readable error colour for failures. Every state also has a word/icon; colour is not the only signal. Check contrast in dark and light themes.
- Keep remembered folding, running/failed default expansion, Expand/Collapse all, search, filters, keyboard navigation, and the details panel. Confirm whether the missing summaries/controls in the screenshot are clipping or a rendering problem while implementing.
- The colour refinement is scoped to Agents and the new Files controls; preserve terminal syntax palettes and the meaningful battery thresholds.

## Files: checkout dropdown and branch context

- Keep the project selector. Next to it, show a checkout dropdown with a branch icon, branch name, and worktree directory name. Example: `feat/orders · orders-review`.
- Opening the dropdown lists the main checkout and linked worktrees of the selected repository, with branch, folder, and current selection. Selecting an entry switches the tree/editor to that directory; it does not run `git checkout`, create a branch, or move an agent.
- Discover registered worktrees using `git worktree list --porcelain -z`. Include siblings, nested worktrees, and paths elsewhere; proximity alone does not authorize unrelated folders. Validate each selected target through the known-project/repository checks.
- Show detached HEAD as `Detached · <short SHA>`, an unborn branch by name, missing/prunable worktrees as unavailable, and non-Git projects as `Folder · No Git branch`.
- Keep tabs, preview state, expanded tree folders, and active file separate per canonical checkout path. Fix the current project-only persisted Files tab key so paths from one worktree do not reopen in another.
- Retain unsaved documents when switching, restore them when switching back, and include them in the existing quit warning. Close an editor only through the normal unsaved-changes flow.
- Keep branch/worktree context visible above the tree and in the status bar. Full paths are available in the dropdown/tooltip and through Copy path. Refresh metadata after external branch changes or added/removed worktrees, without resetting the user's current selection.

## Files: Delete

- Add `Delete…` at the bottom of tree file/folder context menus, separated from navigation and copy actions. No destructive action on terminal-output context menus.
- Confirm with the relative path and destination: **Move to Recycle Bin** on Windows, **Move to Trash** elsewhere. Cancel is the safe default. Use Electron's trash operation; never silently fall back to permanent deletion.
- For folders, make the scope explicit and check for open/dirty descendant documents. If any are dirty, list them and require explicit consent to discard their editor changes as part of the deletion; cancellation preserves all documents.
- Main-process validation must reject the checkout root, Git metadata, outside paths, traversal, and unsafe symlink resolution. Use the existing known-folder gate plus deletion-specific validation; a path authorized for reading is not automatically safe to remove recursively.
- Revalidate immediately before trashing. Surface permission, missing-path, and trash failures. On success refresh the tree/Git status and close affected clean documents; never claim success if the operation failed.

## Detected run commands

- A `Run` control beside the checkout dropdown opens a compact panel with a command selector, full command, working directory, detection source, Run, Stop, and Edit commands.
- Detect from files only; discovery does not execute scripts, build projects, evaluate MSBuild, install packages, or start services.
- First-release detectors cover .NET and Node projects. Other stacks receive the same custom-command fallback rather than guessed commands.
- .NET: discover `.sln`, `.slnx`, runnable `.csproj` files, and `Properties/launchSettings.json`. Offer solution Build/Test plus Run/Watch for executable/web projects. `dotnet run` targets a project, never a solution. Show multiple runnable projects/profiles separately; do not choose one arbitrarily or start all projects. Exclude libraries/test projects from Run. Ignore unresolved/complex settings rather than executing them to discover their meaning.
- Node: read `package.json` scripts and select the package manager from `packageManager`/lockfiles. Show available `dev`, `start`, `build`, and `test` scripts, with their package directory. Surface lockfile conflicts instead of choosing silently.
- Bound discovery by depth/file count/time and skip `.git`, dependencies, build output, generated and inaccessible folders. Always allow an explicit solution/project location when the scan reaches its limits or misses a nested application.
- Show `Detected from …` for each suggestion. Users can edit a suggestion, add a named command, choose its working directory, and save a local override for the configured project plus checkout-relative target. Overrides are stored in Dawsha settings and do not modify repository files. Custom overrides win on rescan.
- If detection finds nothing, show `No run commands found` with Add command and Choose solution/project. If a command exits unsuccessfully, preserve its output and offer Edit command / Run again. Do not silently replace the command or discard previous output.
- Only an explicit Run click starts a command. Capture the selected checkout and command at launch. Use a **dedicated run terminal**, never inject commands into a Claude/Codex/Gemini prompt or the currently focused agent.
- Show output, running/exited/failed state, exit code, and Stop for that run. Stop terminates its own process tree only. Switching checkout leaves existing runs bound to their original checkout and clearly names them in the run selector. Require a stop/restart choice for an already-running command; do not launch duplicate servers accidentally.
- Use structured executable/argument data for detected commands; treat edited shell commands as explicitly user-authored. Validate cwd inside the selected allowed checkout, keep launch-profile secrets out of saved command strings/log metadata, and report missing SDK/package manager/port conflicts without automatic system changes.

## Key states and validation

- Agents: empty, loading, filtered, running/failed/finished groups, long titles, 1/31/400 agents, folded summaries, narrow view, keyboard, dark/light, reduced motion.
- Files: switch between equal relative file names in different worktrees; dirty files across switches; branch rename, detached/unborn/non-Git state; deleted worktree; refresh; denied paths and symlinks; Delete cancel/failure/success; dirty folder descendants.
- Run: .NET solution with multiple apps, launch profiles, no runnable app, Node monorepo and conflicting lockfiles, no config, scan limits, missing tools, failed process, stop/restart, output retention, and switching checkout during a run.
- Implementation follows failing unit/integration tests for discovery, settings, path validation, and commands, then focused end-to-end tests for the above flows. Verify 1024×728 and a wide window. Use one final whole-change review, then CI; merge/tag only under the release authorization for this version.
