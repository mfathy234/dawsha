# Dawsha 1.8.3: Files feels like VS Code

Mockup: `docs/redesign/files-nav/index.html` (https://claude.ai/artifact/4D9PL5PPpaWthuxR7wbE5A). Open it and match it for the "Jump first" direction. Contract: `src/shared/codeNav.ts`.

No ReSharper-style formatter. Files respects `.editorconfig` when a project has one.

## Keys

| Key | Action |
|---|---|
| F12, Ctrl+click | Go to Definition |
| Ctrl+F12 | Go to Implementation |
| Shift+F12 | Find All References |
| Alt+Left, Alt+Right | Back, Forward |
| Ctrl+T | Go to Everything: files, symbols, text |
| Ctrl+Shift+O | Go to Symbol in this file (scope the sidebar filter, `builtin.ts`, to the grid view) |
| Ctrl+G | Go to Line |
| Ctrl+D | Add next occurrence (multi-cursor) |
| Esc, Enter, arrows | Peek: close, open, move |

## Behaviour (Jump first)

One result jumps in a preview tab with a short line flash. Several results open an inline peek under the cursor line: code left, results right grouped by file. References always peek.

Result states, all from the mockup: exact results carry no label; by-name results say "Best match by name · N other matches"; "No definition found for X" bubble; "X is defined outside this project" bubble with Open in VS Code; status bar text for TypeScript starting, TypeScript stopped with Restart, and C# by name with an install link.

Traps:
- Jumps switch the target tab out of the Changes view.
- Back and Forward store `{path, pos}` and reopen, because a preview tab can be replaced.
- Peek must not change the host doc's `editing` state; plain `e` must not toggle edit while focus is in the peek.
- If the target doc is open and dirty, relocate the hit by searching for the symbol near that line in the buffer.
- Respect the tab cap (`filesState.ts`); a null open result must not lose navigation history.

## Engine (main process)

1. Name search for every language, on the existing `git grep` path in `src/main/filesExtra.ts`, ranking declaration lines first. Must work in non-git folders the same way Find in files does.
2. TypeScript and JavaScript: `tsserver` from the `typescript` package, moved to `dependencies`, in an Electron `utilityProcess`, started lazily on the first request for a project, stopped when the app quits (see `src/main/childProcesses.ts`, `shutdown.ts`). Use name search until it is ready, and if it stops.
3. C#: an LSP client over stdio for `csharp-ls` or OmniSharp found on PATH or in `~/.dotnet/tools`. Choose the nearest `.sln` above the file; with several, the one containing the file's project. Name search until ready. Install on request with `dotnet tool install -g csharp-ls`, only after the user clicks, and report failure plainly.
4. Results outside the project root become `outside: true`, never a read of that file.

All child processes: no shell, `windowsHide`, killed on quit, validated inputs at the IPC boundary. Windows, macOS and Linux.

## `.editorconfig`

Parse with a small, tested parser or the `editorconfig` package, walking up to `root = true`, stopping at the project root. Applied per file:
- `indent_style`, `indent_size`, `tab_width`: CodeMirror `indentUnit` and `tabSize`.
- `end_of_line`: on save, overrides detection. Without it, keep the existing per-file behaviour, and fix mixed endings being normalised silently.
- `insert_final_newline`, `trim_trailing_whitespace`: on save, only when the file was edited. Markdown-safe: the rule applies exactly as configured.

## Editor extras

Inline errors from Problems (with `@codemirror/lint`); fold gutter and indent guides; symbol breadcrumbs; word-level highlights in Changes (`highlightChanges`); multi-cursor (`allowMultipleSelections`); clickable Ln/Col; a regex C# outline, because the legacy mode has no tree.

## Second wave (added by the owner, same release; no autocomplete)

Agent features:
1. Ask an agent from the code: send the selection or symbol to a chosen session with file, line and references.
2. Who changed this line: gutter shows the agent session behind each changed line; clicking opens that session.
3. Unupdated callers: after an agent changes a function or interface, list callers and implementations it did not touch. Name-search results must be labelled as best guesses.
4. One-pass review: next and previous change keys, mark a file as viewed, send all comments to the agent as one request.
5. Follow the agent: a toggle that opens each file as the agent edits it, with changed lines highlighted. Off by default.

Editor features:
6. F8 and Shift+F8 next and previous error; hover for type info.
7. Side-by-side diff in Changes.
8. Stage or revert one change from the gutter. Revert is destructive: confirm, naming the change.
9. F2 rename across files, with a preview and explicit confirm. Exact engines only; with name search say rename needs a language server.
10. Replace across files, with a preview and a confirmation naming the file and match counts.
11. Sticky scroll.
12. Call hierarchy.

## Third wave (added by the owner, same release)

13. PR flow: from Files or a session, open a PR through the `gh` CLI, read review comments and CI failures, and send them to an agent to fix. Merge stays explicit, with a confirmation naming the PR. Clear state when `gh` is missing or signed out.
14. Built-in browser: a pane or Files tab that previews the running app, with address bar, back, forward, reload and devtools. Sends a screenshot or console errors to an agent. Sandboxed, no node integration, separate session partition, no access to Dawsha's IPC.
15. Config in Files: reads `appsettings*.json`, `launchSettings.json`, `.env*` and similar for the project, and shows them in a Config tab beside Run and Problems in the bottom panel. Shows which file supplies each value and which override wins by environment. Values whose key or shape looks secret are masked until clicked, and are never sent to an agent unasked or logged. Read-only; clicking a row opens the file at that line.
