# Dawsha 1.7.4: Projects sidebar, Files and Agents revamp

Status: approved 2026-10-28 (see Decisions at the end). Mockup: `docs/mockups/1.7.4.html` (open it in a browser; the strip at the top switches view, sidebar/rail and theme). Builds on `feat/1.7.3` (worktree dropdown, safe delete, run commands), which must merge first.

## Intent

1.7.3 added capability to Files and tidied Agents. 1.7.4 rebuilds these surfaces so each reads at a glance:

- **Projects sidebar:** what needs me, and where is work happening?
- **Agents:** what is running, what failed, and what did each agent do?
- **Files:** where am I (project, branch, worktree), what changed, and how do I hand it to an agent?

No new framework. Keep the vanilla `h()` renderer, the existing tokens (`--r-*`, `--s-*`, `--fs-*`, surface ladder), CodeMirror, context menus and the pty layer. Follow the owner's taste rules: no coloured edge bars, pills, decorative dots, caps labels or bordered boxes. State is always a word or icon as well as a colour.

## Projects sidebar

Problems today: every project header shows `+ ⋯ ⌄` all the time; the filter field always takes space; tag text (`· feature`) competes with status; a folded project hides whether anything needs you; Manage projects is a lone link.

- **Waiting on you** section at the top, shown only when it has items. It lists sessions that need input (permission, question, plan approval) across all projects, newest first. A session listed here also stays in its project.
- **Project row:** chevron, name, and branch below it (from the 1.7.3 checkout data). On the right is a quiet `2 live` or `needs you`. `+` and `⋯` replace the count only on hover or keyboard focus. Clicking the row folds the project; fold state is remembered.
- **Session row:** agent mark, title, and age on the right (`4m`, `1h`, `yesterday`). The second line is the status word (`Working · 3 agents`, `Idle`, `Needs you`, `Done`). Tags move to the board and tooltip.
- **Header:** title with search, add project and collapse icons. Search opens an inline filter (Ctrl+Shift+F) that matches projects and sessions and unfolds the matches.
- **Sort menu:** Recent activity (default), Name, Manual (drag), plus "Hide projects without sessions".
- **Footer:** Add project and Manage.
- **Rail mode** (56px): monogram per project, `!` in needs colour or a run count, the current project tinted. Clicking a monogram opens a flyout with that project's sessions. Rail state is remembered.
- **Project `⋯` menu:** New session, Open in Files, Open terminal here, Pin to top, Rename…, and last, after a separator, `Remove <name> from Dawsha…`. That item confirms with the project name in the message and on the button, and explains that the folder stays on disk.

## Agents

Problems today: three loose counts plus a separate filter row; groups are cards with lots of empty width; you only see details after selecting, and the detail lacks what the agent is doing now and what it touched.

- **Header:** `Agents`, then a segmented state filter with counts, `All 7 · Running 2 · Failed 1 · Done 4`, which replaces the counts and the filter. Today's tokens and cost sit at the right.
- **Tool row:** search (agents, tasks, file names), Project ▾, Time range ▾, Agent ▾ (multi-select), a `List | Timeline` switch, and `⋯` (Expand/Collapse all, Show automatic reviews, Export visible as Markdown).
- **List:** group header is agent mark, session title, and `project · N agents` below. Per-state counts go on the right with running and failed first. Agent rows have a state icon, task, state word, duration, and a second line with the **current tool call while running** or the **result/first error line once finished**. No cards: flat rows on the canvas with hover and selected fills.
- **Detail pane (always visible ≥ 900px):**
  - Title, then state, duration, agent, and a link to the parent session.
  - Actions: Open transcript and Go to session. Running agents also get `Stop…`, which opens a confirm dialog that names the agent in its message and button. Failed agents get Ask session to retry; finished agents get Copy result.
  - Task: the prompt the agent was given.
  - Live activity: the last tool calls, updating while it runs. Result replaces it once the agent finishes.
  - Files touched: A/M/D with line deltas. Clicking one opens it in Files at that checkout.
  - Usage: tokens, cost, model and start time.
  - When nothing is selected, the pane explains what will appear.
- **Timeline:** one lane per session with a lane per agent below it, on a shared time axis. Bars use the state colour, and a tooltip gives name, state and duration. Clicking a bar selects that agent. This shows which agents ran in parallel and which ones stalled.
- Keep remembered folding, running/failed expanded by default, keyboard (Up/Down rows, Left/Right fold, Enter opens transcript) and the 1.7.3 colour work.
- Below 900px the detail pane becomes a drawer over the list.

## Files

Problems today: a project select, a filter, an All/Changed/Open tab strip and the tree are stacked in the left column; the toolbar has six buttons; the right panel is fixed; run output (1.7.3) competes with the editor.

- **Location button** at the top of the explorer. Line one is the project, line two is the branch and worktree (`feat/dark-mode · acme-web-dark`). One dropdown holds both lists: projects first, then checkouts of the current project. Missing or prunable worktrees show greyed out with the reason, and Copy path and Reveal sit at the bottom. Switching never runs `git checkout` (1.7.3 rule).
- **Explorer sections** replace the filter tabs and fold independently, with remembered state:
  - Changes (n) is a flat list with the folder shown dimmed.
  - Open in sessions (n) shows which session holds each file.
  - The full tree is titled with the worktree folder.
  - The filter field becomes `Go to file… Ctrl+P` and opens the existing quick-open.
- **Tabs:** a preview tab is italic, a dirty tab shows `●`, and tabs are kept per checkout (1.7.3).
- **Breadcrumb bar:** the path, a `File | Changes +31 −7` switch (inline diff with +/− rows), **Send to agent ▾**, `⋯` and an inspector toggle.
  - Send to agent ▾ lists live sessions for this project, then "New session with this file…" and "Copy as @mention". It replaces "Add to prompt", which always targeted one session.
  - `⋯` holds Edit (E), Open in VS Code, Copy path, Copy relative path, Reveal, and `Delete <file>…` last. Delete uses the 1.7.3 trash flow with the file name on the button.
- **Bottom panel:** 1.7.3 run commands move here, VS Code-terminal style, with one tab per run (`Run · dev`, `Run · test`) plus Problems. Each run tab has a command picker, Restart and Stop. The panel can be minimised, and its height and minimised state are remembered. A running command also shows in the status bar (`dev running · :5173`).
- **Inspector** (toggle, remembered, hidden under 1180px) has two tabs:
  - Outline.
  - Activity: agents that read or edited this file, with live ones first, then recent commits touching it.
- **Status bar:** branch, delta vs base, running command, cursor, language, and read-only hint.

## Files: new features for how the owner works

Drawn from past sessions:
- reviewing agent output before PRs;
- reading `docs/plans/*.md` and `docs/mockups/*.html`;
- comparing `docs/screenshots` after UI changes;
- sessions that span several repos (Microtec_ERP + Keycloak Providers + MicrotePackages).

The explorer gets three modes under the location button: **Files | Search | Review n**.

- **Search (find in files, Ctrl+Shift+F):**
  - Runs ripgrep in the main process, scoped to the selected checkout, and respects `.gitignore`.
  - Options: Match case, Whole word, Regex, and an include glob.
  - Results are grouped by file with line snippets; click one to open at that line. Results are capped, and the cap is stated.
- **Review (human review of agent changes):**
  - Steps through changed files with viewed ticks (N / P).
  - Click a `+` line in Changes to add a comment.
  - "Send n comments to agent" posts one message to the session that made the changes, with `file:line` references and an optional overall note.
  - Commit… shows a message drafted from the session summary, editable, with file selection. It reuses `gitCommit.ts` and hooks run normally.
  - Discard file… confirms and names the file.
- **Agent blame in Changes:** a gutter mark on each added line shows which agent or session wrote it, with the task and time in the tooltip. Uses edit records from session transcripts (the same data as "Sessions that touched it").
- **Markdown and HTML preview:**
  - `.md` gets a Preview | Source switch, with Preview as the default for docs.
  - `.html` renders in a sandboxed iframe (scripts on, network and navigation off), with Open in browser.
- **Image view with compare:** PNG/JPG/SVG/WebP preview. For changed images, "Compare with main" gives a drag-to-split before/after.
- **Linked repos:** the location menu lists other repos your sessions edited together with this project (from session file records). One click switches to them; nothing is added to the project list automatically.

## Dark mode: Dawsha Cards refined (Files, Agents and panes)

The owner uses **Dawsha Cards** (`src/shared/themes.ts`, `dawsha-cards`). Its problems come from the derived ladder (`themeLadder.ts` `darkLadder`):

- **Surface steps too small.** `raised` is only +4% white over the pane, so selected and hover rows in Files and Agents almost vanish, and every view reads as flat near-black.
- **Terminal well too dark.** The well is derived 60% of the way toward a near-black canvas (≈ `#0d0f14` against a pane of `#151922`). Every pane becomes a black hole inside a card, with an inset shadow and a second frame.
- **Green overloaded.** One green is the accent, the focus border (2px), the cursor and "done". The focused pane shouts, and done states look like buttons.
- **Text halation.** `#d9dee8` on near-black is harsh over long sessions, and tertiary text (`#5d6576`) is too dim to read.

Proposed values (mockup: Cards today / Cards refined; Panes, Files and Agents):

| Token | Today | Refined |
|---|---|---|
| canvas | #0a0c10 | #0c0e13 |
| chrome | #0d1015 | #11141a |
| pane | #151922 | #181c24 |
| raised | ≈#1e222b (+4%) | #222731 (+7%) |
| overlay | ≈#282b34 | #2b313d |
| well / terminal bg | ≈#0b0d12 | #14171e (one shade below the pane) |
| text / muted / faint | #d9dee8 / #8a93a6 / #5d6576 | #d4d9e2 / #9ba4b6 / #6e778a |
| done | accent green | sage #86c5a8 |
| focus | 2px accent border | 1px white 24% ring + soft shadow |

- **Panes:**
  - The terminal sits flush in the card: no inset well, no inner margin or radius, just a hairline seam under the header.
  - Focus is a neutral ring plus lift. Unfocused panes render terminal text at `t-dim` (#aab2c1) with a hollow cursor.
  - Needs-you panes get an orange edge ring and keep their orange state word.
  - Pane buttons show on hover or focus.
- **Files:**
  - Selected tree rows get raised plus a 1px ring.
  - The editor uses the pane colour, with a 3% current-line tint.
  - The syntax palette is softened to match: less neon purple, yellow toned down.
- **Agents:** the selected row has a ring. Running is blue, done is sage, failed is coral, and the state word always goes with the icon.
- **Rollout:**
  - Apply this to Dawsha Cards first, then retune the `darkLadder` constants so Dawsha, Graphite Cards and other derived themes benefit.
  - Terminal ANSI colours stay as they are.
  - Add a unit test for each dark theme checking text/muted ≥ 4.5:1 on pane, well and raised.

## Usage meter (top bar)

- **Root cause:** `accountLimits()` (`src/shared/topbarSummary.ts:41`) returns the focused pane's limits. If that pane has none, it returns **whichever pane first has any**. Nothing shows which agent the numbers belong to. So switching between a Claude and a Codex pane silently swaps 62% for 1%. Focusing a Gemini pane, or a pane that hasn't reported yet, shows another agent's numbers.
- **Fix the data:**
  - Limits are per account, so keep the latest windows **per agent kind** with a timestamp, not per pane.
  - The meter shows the focused pane's agent. If that agent has nothing, it says "no limits reported" and never borrows another agent's numbers.
- **Fix the UI:**
  - The meter starts with the agent mark and name (`✳ Claude 5h ▮▮▮▮ 62% week ▮ 18%`).
  - Clicking it opens a popover with every agent: both windows, reset times, data age ("updated 4m ago"), and the focused one marked. There's also a link to the Usage view.
  - Stale data (older than its reset) is shown as stale rather than as current.
- Tests:
  - Unit tests for the per-agent selection: focused Claude, focused Codex, Gemini with no data, and a pane with no data yet.
  - An e2e test that switches focus between Claude and Codex panes and checks that the meter's label and numbers follow the focused pane.

## Decisions (2026-10-28)

The owner approved the mockup and asked for everything to ship in **1.7.4**, through PR, merge, website and tag.

- **Scope:** everything in this document is in 1.7.4. Secret masking was dropped.
- **Session names stay visible.** Session titles appear in full (ellipsis only when space runs out, with the full title in the tooltip) everywhere they appear today:
  - sidebar session rows and Waiting on you;
  - the rail flyout;
  - Agents group headers and the detail link;
  - pane headers.
  No redesign replaces a session's name with a generic label.
- **Dawsha Cards is refined in place** and keeps its id `dawsha-cards` and name "Dawsha Cards".
- **Waiting on you** lists only sessions blocked on the user (needs you, permission, question, plan approval).
- **Agents Stop** ships only if there is a reliable way to stop one background agent without killing its parent session. Otherwise it is left out, and the detail pane offers Go to session instead.
- **Files bottom panel:** run commands and Problems only, no plain shell.
- **Rail mode** is manual and remembered.
- **Review comments** are inserted into the target session's prompt **without submitting** (like Add to prompt today), and that pane is focused, so the user presses Enter. Nothing interrupts a running agent.
