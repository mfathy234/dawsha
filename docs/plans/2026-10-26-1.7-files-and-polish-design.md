# Dawsha 1.7: Files view and visual cleanup

Approved 2026-10-26. Mockups: https://claude.ai/artifact/QgRxbpYXTCNJaQ811B7aST

## 1. Files view (new tab)

A light editor for looking at project files without leaving Dawsha.

- **Where.** A new top tab, Files (Ctrl+Shift+E), after Agents. It opens on the focused session's project and
  worktree. A project switcher sits above the tree.
- **Tree.** Read one folder at a time in main. Skip `.git`, `node_modules`, `bin`, `obj`, `dist` and anything git
  ignores. M/A/D badges come from `git status --porcelain`. Filters: All · Changed · Open in sessions. A debounced
  folder watcher refreshes it, and only while the tab is visible.
- **File, then changes.** Opening a file shows the file itself, read-only, with selection and copy (Ctrl+C and the
  context menu) always working. The **Changes** toggle swaps to an inline diff against the merge base with `main`.
  Pressing it again returns to the file.
- **Editing.** CodeMirror 6, with language packs loaded when needed. E or Edit switches to editing, and Ctrl+S saves.
  If the file changes on disk while it is being edited, a bar offers Reload theirs / Keep mine. Binary files and files
  over 2 MB show a notice and Open in VS Code.
- **Tabs.** A single click opens a preview tab (italic) and a double click pins it. Open tabs are remembered per
  project.
- **Right panel.** Sessions that touched the file, from the edit lines the session timeline already parses. Clicking
  one goes to the session. An outline comes from CodeMirror's syntax tree.
- **Actions.** Add to prompt types `@path` (plus the selected line range) into the focused session. Open in VS Code,
  Copy path.
- **Ctrl+P everywhere.** Fuzzy search over `git ls-files`, cached per worktree, with a preview. Enter opens the file in
  Files and Alt+Enter adds it to the prompt.
- **Safety.** One validator in main for every path. It resolves the path and its symlinks and refuses anything outside
  the project root. Reads are capped at 2 MB and saves go to the same validated path only.

## 2. Visual cleanup (undo the 1.6.2 "boxed" look)

- **Pane header.** Remove the 3px coloured state bar and the bordered recap box. State becomes a dot plus a word,
  with no pill border. The recap becomes plain muted text under the title, with a setting to hide it. Panes lose their
  outlines, and the focused pane is shown with a soft lift (shadow and a slightly lighter surface).
- **Popups and pickers.** Use fill and shadow instead of borders. Focus becomes a faint 1px ring (keyboard focus
  stays visible). Remove the 2px green ring in the resume picker.
- **Sidebar rows.** Time and cost move to a second line under the name. × shows only on hover or focus and never
  covers text.
- **Agents tab.** Replace the timeline with a list grouped by session (GitHub Actions style), with a small waterfall
  bar per agent scaled to its own session. Running agents first, never clipped. Chosen by the owner 2026-10-26.
- **Dimming panes you're not in.** Off by default. A "Dim others" toggle in the top bar next to Grid/Board, also in
  Settings and as a palette command.

## 3. Tag colours

- **Automatic tag.** From the branch: `feature/` → Feature; `fix/`, `bug/`, `hotfix/` → Bug; `docs/` → Docs;
  `review/` → Review.
- **No branch.** Guess from the conversation (title and first prompt): fix/bug/error/crash/broken → Bug,
  add/feature/implement/build/new → Feature, review → Review, docs/readme → Docs. No match means no tag.
- **Manual tags win.** A manual tag always beats an automatic one, and the automatic tag is marked as such in the
  tooltip.
- **Visible.** Each tagged row gets a coloured edge and chip in the sidebar, the board and the pane header.
- **Setting.** "Colour sessions by tag" (on by default), also a palette command. When it is off there are no edges or
  chips, but tagging still works.
