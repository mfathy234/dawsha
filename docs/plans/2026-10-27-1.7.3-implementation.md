> For agentic workers: use the approved design and task ownership below. Follow test-first implementation. The owner prefers broad work areas and one final review, rather than a reviewer after every small task.

**Goal:** refine Agents and make Files support selecting existing worktrees, safe Delete, and detected/editable run commands.

**Spec:** `docs/plans/2026-10-27-1.7.3-design.md` (approved by “go on”).

## Global constraints

- Version scope is 1.7.3. The owner subsequently authorized commit, push, PR, merge and tag after local implementation.
- Preserve the main checkout's untracked files. Work in `dawsha-wt-173` on `feat/1.7.3`.
- Existing-checkout selection must not run git checkout, create worktrees, or move agents.
- Delete uses Trash/Recycle Bin only, validates paths in main, and handles dirty documents explicitly.
- Discovery never executes repo code. Only Run starts a command, in its captured checkout.
- Keep commands editable and locally saved. Preserve error output and offer correction.

## Review focus

1. Equal relative file names across worktrees must not share document/tab state.
2. Symlinked directories and Git metadata must never be trashed or scanned outside an allowed checkout.
3. Rapid checkout/project switches must not apply stale metadata, discovery, or watcher results.
4. Stopping/restarting one command must not terminate an agent or a different run.
5. Complex launch settings, multiple startup projects, and package-manager conflicts need visible correction paths rather than silent guesses.

## Implementation notes

- Files switches to canonical existing checkouts and stores tabs by project plus checkout. Async selection, open-file, discovery, and refresh results are guarded against stale targets.
- Delete validates paths in main and uses system Trash only. Files is temporarily inert while confirmation/trash is pending, so new edits cannot slip past the captured dirty-document consent.
- Run discovery supports executable/web .NET projects, JSONC launch profiles, solution Build/Test, Node scripts, and workspace package-manager inheritance. Conflicting metadata offers correction. Detection does not execute project code.
- Detected commands use structured arguments. Explicit saved shell overrides remain local settings and are excluded from portable exports. Every run captures its checkout, retains bounded output, and owns its process tree. Shutdown awaits runner disposal.
- Run output is a dedicated read-only panel. Its keyboard handling prevents file-editor shortcuts from affecting an open source tab.
- The whole-change review found three issues: pending-delete edits, skipped Node `packages` folders, and package-manager inheritance. All were fixed and verified. No remaining security findings were reported.
